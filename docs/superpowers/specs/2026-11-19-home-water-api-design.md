# Home Water API Design

- **Intent:** Replace Home's hardcoded Water sample with the authenticated daily summary and show actual intake, goal progress, and individual logs.
- **Goals:** Use the existing Water repository/API; refresh it with Home; preserve the original two-column Water card; show total and goal in litres with a capped progress ring and compact drink columns using a fixed 500 ml visual scale; preserve loading, error/retry, empty, localization and accessibility behavior.
- **Non-goals:** Change the Water API, daily goal rules, persistence, or standalone Water screen; add dependencies.
- **Constraints:** `GET /api/water/daily-summary` owns `totalMl`, `goalMl`, `percent`, and `logs`; local day/timezone comes from the Water repository. The Water chart must display only recorded events and not infer values for missing periods.
- **Approaches:** (1) Reuse the authenticated Water repository and preserve the reference's compact Home card (selected; keeps API ownership and visual hierarchy intact). (2) Add a new Home endpoint or backend DTO (rejected; duplicates an existing authenticated daily contract). (3) Keep the mock chart and only replace the headline value (rejected; leaves the requested visualizations inaccurate).
- **Implementation choices:** Integrate Home with `useWaterDaily` and add an explicit reload path keyed by Home refresh/focus; display the returned total/goal in litres in the original two-column card; render one compact chronological column per log with fixed 500 ml full-height scale and no chart explanation text. Put exact event details in the accessible card label. No Backend source change is expected.
- **Acceptance:** Home shows API total/goal in litres and goal progress; each returned log appears as a compact local-time-ordered column on a fixed 500 ml scale; no explanatory text is shown under the value; empty/error/loading states do not show samples; refresh reloads Water; EN/VI copy and screen reader labels are provided.
